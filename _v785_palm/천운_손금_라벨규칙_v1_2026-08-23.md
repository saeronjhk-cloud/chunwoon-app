# 1. ★★실측 — 라벨 규칙보다 먼저 알아야 할 4가지

★**이 절은 재조사 금지입니다.** 2026-08-23 에 `palm-api/` 파일을 직접 열어 확인했습니다.
★라인 번호는 `palm_detector.py` (22,651 B · 2026-04-15) 기준입니다.

## 1-1. ★U-Net 은 **이진 마스크**를 냅니다 — 3선 분리 출력이 아닙니다

```python
# palm-api/unet_model.py:96
class UNet(nn.Module):
    def __init__(self, n_channels=3, n_classes=1):   # ★n_classes = 1
```
⟹ `checkpoint_aug_epoch70.pth` 는 「여기가 **선이다/아니다**」만 답합니다.
⟹ **어느 선인지는 U-Net 밖의 후처리**가 정합니다 (원본 `yeonsumia/palmistry` 는 K-means).

| | |
|---|---|
| **Phase 0** (기존 체크포인트 평가) | 4색 라벨을 **이진으로 합쳐** 씁니다 (`1·2·3·4 → 1`) |
| **선별 검출률** | 4색 라벨이 **있어야만** 잽니다 · ★FATE 는 **따로** 냅니다(§2-3-5) |
| **Phase 1.5** (재학습) | `n_classes=5` 로 직접 학습하는 선택지가 생깁니다 (배경 포함) |

⟹ ★**4색으로 칠하면 정보 손실이 0입니다.** 이진은 4색에서 만들 수 있지만 역은 불가능합니다.
★개발계획 `0-2`(「마스크 → 선 3종 분리」)는 **U-Net 안이 아니라 후처리 단계**입니다.

## 1-2. 기존 코드도 **4선**을 분류했습니다 — ★우리와 클래스 수는 같아졌습니다

```
palm_detector.py:6     "classify as life/head/heart/fate"
palm_detector.py:352   [('life','생명선'), ('head','두뇌선'), ('heart','감정선'), ('fate','운명선')]
```
★인수인계·개발계획은 「3대선」만 말했는데 **코드에는 네 번째가 있었습니다.**
★★**2026-08-26 정정**: 초판은 이를 근거로 fate 제거를 주장했으나, ★제이 결정으로 **FATE 는 포함**됩니다(§2-3).
⟹ ★**클래스 수가 같다고 기존 구현을 되살리는 것이 아닙니다.** 기존 `fate_score` 는 `is_vertical`
 단독 4점인데 그 입력이 §1-4 에서 **난수**로 확인됐으므로 ★**폐기 유지**입니다.
⟹ ★**이것이 「의사난수 40%」의 원인은 아닙니다** — §1-4 를 보십시오.

## 1-3. ★★`_fallback_line` 은 **4개 키 전부**에 걸립니다 (초안의 국소화 오류 교정)

```python
# palm_detector.py:352-381
for key, name in [('life','생명선'), ('head','두뇌선'), ('heart','감정선'), ('fate','운명선')]:

    else:

        ... depth=1, detected=False
```
`_fallback_line` 은 `life` · `head` · `heart` 전용 기하를 각각 갖고, ★**`else:` 가 fate 기하이자
 동시에 catch-all 기본값**입니다.

⟹ ★★**날조는 운명선만의 문제가 아니라 전역 결함입니다.**
⟹ ★**`fate` 만 빼면 함수는 그대로 남아 미래의 어떤 키든 조용히 삼킵니다.**
⟹ ★★**Phase 4 게이트를 함수명 grep 으로 만들면 이 상태를 통과시킵니다** — §10-1 **P-6** 참조.

## 1-4. ★★★「의사난수 40%」의 실체 — **실측 3가지** (신규 확정)

2026-05 노션 원문은 「깊이·특이점: 부분 측정 + 의사난수 · 의존도 ≈40%」라고만 적었습니다.
★**무엇이 난수였는지는 기록이 없었습니다.** 이번에 코드에서 확정했습니다.

### ① `depth` 는 **측정된 적이 없습니다** — 상수입니다
```python

palm_detector.py:378     depth=1,     # ★폴백한 모든 선
```
⟹ 노션이 말한 「**깊이**」가 바로 이것입니다. **재는 코드가 존재하지 않습니다.**

### ② ★★분류기의 입력값 자체가 난수입니다 — 왕복 컨투어
`_thin_lines` 가 1픽셀 골격을 만들고, `findContours(…, RETR_LIST, CHAIN_APPROX_NONE)` 가
그 골격을 **왕복**하는 컨투어를 냅니다. 따라서 `pts[0] ≈ pts[-1]`:
```python
palm_detector.py:284-289
dx = pts[-1][0] - pts[0][0]        # ★≈ 0
dy = pts[-1][1] - pts[0][1]        # ★≈ 0
angle = np.arctan2(dy, dx)         # ★★사실상 난수
chord = np.sqrt(dx**2+dy**2)+1e-6  # ≈ 0
curve_ratio = total_len / chord    # ★폭주
```
| 파생값 | 실제 거동 |
|---|---|
| `is_horizontal` (`abs(angle)<0.7 or >2.4`) | ★**동전 던지기** |
| `is_vertical` (`0.8<abs(angle)<2.3`) | ★**동전 던지기** |
| `curve_ratio > 1.3` | ★**항상 참** ⟹ life 가 +3 을 공짜로 받습니다 |
| `total_len` | ★실제 길이의 **약 2배** |
| `curvature` 출력값 | ★무의미 |

⟹ ★★**`_classify_lines` 는 분류기가 아니라 난수기입니다.**

### ③ 배경 채널이 걸러지지 않습니다 (Caffe 경로 = ★실제 배포 경로)
```python
palm_detector.py:167-176
# 주석: "The channel with the MOST pixels is likely background → skip it"
```

★게다가 채널별 **min–max 정규화**(`:147-151`) 때문에 **죽은 채널조차 반드시 255 픽셀을 갖게 되어**
 임계 80 을 통과합니다 ⟹ **6채널 전부가 「선 후보」를 냅니다.**
★그리고 `_extract_palm_region` 은 **21개 랜드마크 전체의 convex hull**(=손가락 포함) + 8% 팽창이라

### ⟹ ★★이것이 Phase 0·2 에 미치는 영향

## 3-1. `RLC` (1 · 생명선)
| 축 | 규칙 |
|---|---|
| **시작** | 손바닥 **노쪽(엄지 쪽) 경계**, 검지 MCP 와 엄지 사이 |
| **진행** | ★**엄지두덩(thenar eminence)을 감싸며 활처럼** 손목 방향으로 |
| **끝** | ★**손목 주름에 닿기 전에 멈춥니다.** 손목 주름은 **칠하지 않습니다** |

## §1. Part 1 — 도메인 확인 (자료 미제시)

**Q1. 손바닥 주름의 해부학적 실재성**
1. 손바닥의 주요 주름(이른바 「손금 3대선」)은 **해부학적으로 실재하는 구조물**입니까?
   실재한다면 **정식 해부학 명칭**을 적으십시오.
2. 이 주름들은 **언제 형성**됩니까? 후천적입니까, 태생기에 형성됩니까?
3. 유전·발생학적 요인이 관여합니까?
4. ★**의학적으로 의미가 알려진 손바닥 주름 소견**이 있습니까? 있다면 무엇과 연관됩니까?

**Q2. 곡선·관형 구조 세그멘테이션의 평가 지표**
1. 손금선처럼 **이미지 면적의 1~2% 만 차지하는 얇은 곡선**을 세그멘테이션할 때,
   `Pixel Accuracy`·`F1`·`IoU` 중 **어느 것이 부풀려지기 쉽습니까?** 그 이유를 수식 수준에서 설명하십시오.
2. 어떤 논문이 **F1 99% 대**와 **mIoU 0.5 대**를 동시에 보고했다면, 두 수치의 관계를 어떻게 해석해야 합니까?
3. ★**연결성(topology)을 보존하는지**를 재는 지표를 아는 대로 열거하십시오.
   각각의 **정식 명칭·제안 논문·연도**를 함께.
4. 손금선 검출의 **합격 기준**으로 무엇을 쓰겠습니까? 구체적인 지표와 임계값을 제시하십시오.

**Q3. 데이터셋**
1. **손금선(주요 3선)이 픽셀 단위로 라벨링된 공개 데이터셋**이 존재합니까?
   존재하면 **명칭·규모·라이선스·접근 조건**을. 모르면 「불명」.
2. 손바닥 이미지 데이터셋(라벨 없는 것 포함)은 무엇이 있습니까?
3. ★라벨이 없는 데이터셋을 쓰려면 **직접 라벨링**해야 합니다.
   얇은 곡선 3개를 라벨링할 때 **한 장당 소요 시간**과 **라벨러 간 일치도(IAA)** 는 어느 정도로 예상됩니까?

**Q4. 소량 데이터 학습**
1. 손금선 세그멘테이션 U-Net 을 **처음부터** 쓸 만하게 만들려면 라벨 이미지가 **몇 장** 필요합니까?
   근거와 함께. 모르면 「불명」.
2. **전이학습**(혈관·도로·필기선 등 유사 곡선 도메인)이 유효합니까? 어떤 사전학습이 좋습니까?
3. 촬영 조건(조명·각도·피부색·손 크기)의 다양성이 부족하면 무엇이 먼저 무너집니까?
4. **증강(augmentation)** 중 이 도메인에서 **해로운** 것이 있습니까?

**Q5. 다음 각 진술이 사실입니까?** 사실/거짓/불명 + 근거.
1. 「MediaPipe Hands 의 21개 랜드마크에는 생명선·두뇌선·감정선의 시작점과 끝점이 포함되어 있다.」
2. 「clDice 는 중심선(skeleton) 기반 유사도로 관형 구조의 위상을 보존하도록 설계된 지표이자 손실 함수이며, CVPR 2021 에 발표되었다.」
3. 「손바닥의 주요 주름은 출생 후 손 사용 습관에 의해 형성되므로 유전적 요인이 없다.」

**Q6. 「검출됐다」를 언제 선언할 수 있는가**
1. 세그멘테이션 결과를 **「이 선을 찾았다」로 선언할 신뢰도 기준**을 어떻게 설계해야 합니까?
2. 3개 선 중 2개만 찾았을 때 **부분 결과를 주는 것**과 **전부 거부하는 것** 중 무엇이 옳습니까?
3. ★모델이 **아무것도 못 찾았는데 무언가를 출력하게 만드는** 설계 실수의 전형을 열거하십시오.

## §2. Part 2 — 실제 상황 (실측)

### 자료 A — 제품
한국어 운세 웹앱. 사주·궁합·타로·꿈해몽·**관상**·작명 등 9개 상품군.
각 상품은 **무료 버전 + 유료 리포트(₩4,900)** 구조. 회원가입·로그인 없음.

### 자료 B — ★손금은 한 번 만들었다가 **의도적으로 삭제**됐다
2026-05-15, 풀스택(유료 리포트·PDF 포함)까지 완성한 손금 기능을 **1,640줄 순삭제**했습니다.
삭제 사유는 버그가 아니라 **정직성**입니다. 당시 자체 평가:

```
· 손금 위치   : MediaPipe Hands 21 랜드마크는 손가락 관절만 감지.
               손금 주름 자체는 감지 못함 → "여기쯤 있을 것"으로 추론
· 깊이·특이점 : 부분 측정 + 의사난수
· 점수        : 측정값 + 의사난수 ±7점
· 의사난수 의존도 ≈ 40%
운영자 결단   : "진짜가 아니면 삭제하는 게 나을 것 같아."
```

★같은 시점에 **관상은 유지**했습니다. 판단 근거로 기록된 대조:

| | 손금 | 관상 |
|---|---|---|
| ML 랜드마크 | Hands 21개 | FaceMesh 468개 |
| 측정 대상 | 손금 주름 (랜드마크는 **관절만**) | 얼굴 부위 **직접** |
| 위치 | **추론** | **실측** |
| 의사난수 의존 | ≈40% | ≈5% |

⟹ 당시 결론: **「측정 정확도가 기능 가치를 결정한다」**

### 자료 C — ★그런데 코드를 다시 열어보니 다르다 (2026-08-23 실측)
삭제된 것은 프런트엔드였고, **백엔드 자산은 남아 있습니다.**

```
palm-api/
  unet_model.py                 "U-Net with Context Fusion Module for Palm Line Segmentation"
  checkpoint_aug_epoch70.pth    ★55MB · epoch 70 · augmentation 적용된 학습 결과
  palm.caffemodel / .prototxt   1.5MB · 별도 경량 모델
  palm_detector.py              22KB · 검출 로직
  main.py                       FastAPI (/detect · /debug)
  Dockerfile                    Cloud Run 배포용
```

★★**그러나 배포된 코드는 U-Net 을 쓰지 않습니다.**
```
requirements.txt : fastapi · uvicorn · opencv-python-headless · mediapipe · numpy · Pillow
                   ★torch 없음
palm_detector.py : torch import 0건 · checkpoint_aug_epoch70.pth 참조 0건
실제 경로        : cv2.dnn.readNetFromCaffe(palm.prototxt, palm.caffemodel)
                   실패 시 → _detect_opencv_fallback (고전 영상처리)
                   그것도 실패 시 → ★_fallback_line() : 랜드마크 비율로 선을 **생성**
```

`_fallback_line('life', lm)` 은 손목·엄지·검지 랜드마크의 거리 비율로 생명선 좌표를
계산해 냅니다. **입력 이미지의 실제 주름과 무관합니다.**

⟹ 즉 당시 「의사난수 40%」의 실체는 **「학습을 안 해서」가 아니라
「학습한 모델을 배포에 넣지 않아서」** 였습니다.

### 자료 D — 가용 자원
- 운영자 1인(비개발자). **AI 코딩으로 개발**.
- Colab 학습 경험 있음 (다른 앱에서 YOLOv8 학습 성공 이력).
- 향후 약 3주간 **매일 1~2시간** 작업 가능. 노트북·인터넷 가능.
- ★**손바닥 사진을 직접 수집할 수 있음**(지인·본인).
- 이 프로젝트는 **엔진 우선** 철학을 씁니다: 가능한 한 결정론적 엔진이 답하고,
  엔진이 못 하는 부분만 LLM 에 넘깁니다. 그리고 **fail-closed** 를 기본으로 합니다
  (판정 불가는 통과가 아니라 거부).

## §3. Part 3 — 결정 질문

**D1.** 손금선 검출을 **「측정」이라 부를 수 있는 최소 조건**은 무엇입니까?
자료 B 의 관상/손금 대조표를 보고, 손금이 그 기준을 **넘을 수 있는지** 판단해 주십시오.

**D2.** 검출 실패 시 무엇을 보여주어야 합니까? 아래 셋 중 고르고 근거를 대십시오.
1. **판독 불가** — "다시 촬영해 주세요"로 종료. 결과 없음.
2. **부분 결과** — 찾은 선만 해석하고 나머지는 "미검출"로 표시.
3. **신뢰도 표시** — 점수와 함께 낮으면 경고.
★그리고 **셋 다 아닌 더 나은 안**이 있으면 제시하십시오.

**D3.** `checkpoint_aug_epoch70.pth` 를 **먼저 평가**하려 합니다.
1. 평가셋을 **몇 장** 모아야 의미 있는 판단이 됩니까?
2. **어떤 지표**로 재야 합니까? (Q2 답변과 연결)
3. ★**얼마가 나오면 「쓸 만하다」**고 판단해야 합니까? 구체적 숫자로.
4. 그 체크포인트가 어떤 데이터로 학습됐는지 **모르는 상태**입니다. 이것이 평가에 어떤 위험을 만듭니까?

**D4.** 우리가 직접 라벨링해 재학습한다면:
1. **몇 장**을 목표로 해야 합니까?
2. 하루 1~2시간으로 그 양이 **현실적**입니까? 아니라면 대안은?
3. 라벨링 품질을 보증할 **절차**를 제시하십시오.

**D5.** ★★**의료적 위험** — Q1-4 에서 답한 의학적 소견과 관련하여,
운세 앱이 손바닥 주름을 분석해 결과를 보여줄 때 **넘지 말아야 할 선**은 어디입니까?
한국 의료법·건강기능식품법 등 관련 규제가 있다면 조문과 함께.

**D6.** 자료 C 의 설계에서 **우리가 놓친 결함**을 지적하십시오. 특히:
1. `_fallback_line` 같은 「실패 시 지어내기」를 **구조적으로 불가능하게** 만들려면?
2. Cloud Run 서버리스에 55MB 모델 + PyTorch 를 올릴 때의 문제는?
3. 사용자가 **아무거나** 찍어 올릴 때(손이 아닌 사진, 흐린 사진) 어떻게 걸러야 합니까?

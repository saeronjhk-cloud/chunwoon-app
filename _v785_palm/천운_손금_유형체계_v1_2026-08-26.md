# 2. ★★유형 축 — v1 은 **3축만**

## 2-0. ★왜 3축인가 (★샘플 부족을 인정합니다)
```
3축 → 2×3×3 = ★18 유형
평가셋 목표 40~50장 ⟹ 유형당 ★평균 2.2장
★그런데 빈도가 치우칩니다 (한국인은 closed·separate 가 최다수)
   ⟹ ★소수 유형은 샘플이 ★0 일 수 있습니다
★★그래서: 유형별 샘플 수를 ★반드시 리포트에 싣고, ★0 인 유형은 「판정 불가」로 둡니다.
★축을 늘리는 것은 ★데이터가 쌓인 뒤입니다. 지금 늘리면 전부 샘플 1 이하가 됩니다.
```

## 2-1. **T1 — 가로 주름 결합** (Park II·III 관계)
| 코드 | 정의 | 한국인 빈도 (Park 2010 · Belay 2022) |
|---|---|---|
| `T1-S` **separate** | PTC 와 DTC 가 **만나지 않는다** | ★**최다수** (한국 84.4 %) |
| `T1-M` **merged** | PTC 와 DTC 가 만나 손바닥을 가로지르는 **하나**가 된다 | 소수 |
| `T1-U` **uncertain** | 판정 불가 | — |

★★**의학 에포님(simian·sydney·suwon)을 쓰지 않습니다** — 라벨규칙 §4-3 규율 그대로입니다.
 ★`merged` + 부속선 유무는 **별도 열**(`accessory_present`)로 갑니다. 정보량은 같고 에포님은 0 입니다.

## 2-2. **T2 — 기시부 결합** (Park I·II 관계)
| 코드 | 정의 | 한국인 빈도 |
|---|---|---|
| `T2-C` **closed** | RLC 와 PTC 가 만나 **공통 주름**을 이룬다 | ★**최다수** |
| `T2-O` **open** | 만나지 않는다 | 2위 |
| `T2-M` **meeting** | 손바닥 노쪽 **경계에서만** 만난다 | 3위 |
| `T2-U` **uncertain** | 판정 불가 | — |

★**한국 사용자 다수가 `closed`** 입니다 ⟹ 「붙어 있다」를 특이하다고 말하면 **사실과 어긋납니다.**

## 2-3. **T3 — 세로 주름 등급** (= FATE · ★우리 정의)
| 코드 | 정의 |
|---|---|
| `T3-C` **clear** | §2-3-3(라벨규칙) 정의를 만족하고 **뚜렷하다** |
| `T3-F` **faint** | 정의는 만족하나 **옅다** |
| `T3-A` **absent** | ★**없다** — 단 ★§4 의 「없음 확정 조건」을 만족할 때만 |
| `T3-U` **uncertain** | 조건 미달 ⟹ ★`absent` 와 **절대 섞지 않습니다** |

★★**`faint` 등급을 둔 이유**: 조사에서 확인된 일본 수상학 실무 지침 —
 *「진했다면 어땠을지를 먼저 보고, 그 결과를 절반 정도로 약화시켜 읽으라」*.
 ★검출 관점에서도 「옅음」은 실재하는 상태이고, ★그것을 `absent` 로 뭉개면 거짓이 됩니다.

## 2-4. ★부수 기록 (유형 축이 **아닙니다** · meta 열로만)
```
accessory_present : none / proximal / distal        (§2-1 보조)
radial_origin     : 1 / 2 / 3                        (Park 2010 노쪽 기시점 수)
variant_*         : branched / forked / broken / cascade   (선별)
hand              : L / R
```
★**이것들을 v1 유형 축에 넣지 않는 이유**: 축이 늘면 유형이 폭발하고 ★샘플이 0 이 됩니다.
 ★**기록은 해 둡니다** — 데이터가 쌓이면 v2 에서 축으로 승격할 수 있습니다.

# 3. ★★엔진 판정 규칙 (고정 원칙 5 — AI 추론이 아닙니다)

★**각 축은 특징값 → 임계 → 등급 + 신뢰도** 로 판정합니다. ★LLM 은 여기 관여하지 않습니다.

## 3-1. 공통 전처리 (Phase0실측 §5-9 그대로)
```
MediaPipe 손 검출 → 손바닥 다각형 ROI(grow=1.12) → U-Net(256×256) → p>0.5 → 조각 분리
★손 미검출이면 ★즉시 「판독 불가」 (fail-closed)
```

## 3-2. T1 판정 (가로 결합)
```
① 조각 중 ★가로 방향(PCA 주축이 손바닥 가로축과 이루는 각 ≤ 40°)인 것을 고른다
② 그 조각들의 ★노쪽 끝 ~ 자쪽 끝 사이 간극을 잰다
③ 손바닥 폭 대비 간극이 ★임계 미만이면 `merged`, 아니면 `separate`
★신뢰도 = 간극이 임계에서 멀수록 높음. 임계 근처면 ★`uncertain`
```

## 3-3. T2 판정 (기시부 결합)
```
① RLC 후보(엄지두덩 경계 쪽)와 PTC 후보(가로)의 ★노쪽 시작부 거리를 잰다
② 손바닥 폭 대비 임계로 closed / meeting / open 판정
★RLC 는 Phase0실측 §5-9-6 에서 ★검출이 약한 것이 확인됐습니다
   ⟹ ★RLC 미검출이면 T2 는 ★`uncertain` 입니다. 추정하지 않습니다
```

## 3-4. T3 판정 (세로 주름)
```
① 라벨규칙 §2-3-3 정의(각 35° · 길이 25 % · 중심선 ±30 %)로 후보를 고른다
② 후보의 ★평균 굵기 / 같은 손 최대 굵기 비율로 clear / faint 판정
③ 후보가 없으면 → ★§4 「없음 확정 조건」 검사 → absent 또는 uncertain
★★기존 `fate_score`(is_vertical 단독 4점) ★재사용 금지 — 입력이 난수였습니다(§1-4)
```

## 3-5. ★★임계는 **전부 미정입니다**
```
★위의 「임계」는 숫자가 ★하나도 정해져 있지 않습니다.
★제이의 유형 라벨이 온 뒤 ★그 라벨을 맞추도록 임계를 정합니다.
★★그리고 임계를 정한 뒤에는 ★고치지 않습니다 — 고치려면 ADR 이 필요합니다.
   (「결과를 보고 임계를 무르는 것」이 2026-05 의 실패 형태입니다)
```

# 10. ★한 문단 요약

★★★**유형 체계 v1 은 「선을 정확히 그리는 문제」를 「어느 유형에 가까운가」로 바꾼 문서입니다**
(제이 제안 · 2026-08-26). ★전환 이유는 실측입니다 — 손가락을 배제하고도 검출 조각이 ★**평균 9.5개**라
3~4선으로 병합하려면 「근접·방향 일치」 판정이 필요한데, ★**그 판정이 틀리면 이어 붙이거나 못 찾거나
둘 중 하나이고 둘 다 2026-05 이 갔던 길**입니다. ★★**유형 접근의 결정적 이득은 「어느 유형에도
뚜렷하지 않음」이 정상 출력이 된다는 것**입니다 — ★지어낼 동기가 구조에서 사라집니다. ★그리고
유형 체계를 ★**우리가 만들 필요가 없습니다** — **Park 2010(한국인 3,216명)** 이 이미 표준 분류를
제공합니다. ⟹ **T1 가로 결합**(separate/merged) · **T2 기시부 결합**(closed/open/meeting) ·
**T3 세로 주름 등급**(clear/faint/absent) ★**3축만** 씁니다. ★축을 3개로 묶은 이유는 정직합니다 —
3축이면 18유형인데 평가셋 40~50장이면 ★유형당 2.2장이고, 빈도가 치우쳐 ★**소수 유형은 샘플이 0**
일 수 있습니다. ⟹ ★**유형별 샘플 수를 반드시 리포트에 싣고 0 인 유형은 「판정 불가」로 둡니다.**
★**의학 에포님(simian 등)은 여전히 쓰지 않습니다** — 중립 코드와 별도 열로 정보량을 보존합니다.
★★**T3 에 `faint`(옅음) 등급을 둔 것이 중요합니다** — 수상학 실무 지침(*「진했다면 어땠을지를 절반으로
약화시켜 읽으라」*)과 정합하고, ★**옅음을 `absent` 로 뭉개면 거짓이 되기** 때문입니다. ★★그리고
**「없음」을 말해도 되는 조건 4가지**를 못박았습니다 — 손 검출 ✓ + T1·T2 가 uncertain 아님 ✓ +
면적 sanity ✓ + 후보 임계 미달. ★하나라도 미달이면 `absent` 가 아니라 `uncertain` 입니다.
★**수상학 문헌 자체가 「초보자가 운명선을 생명선과 혼동한다」와 「옅어서 확대경으로 봐야 보이는
경우가 흔하다」를 명시**하므로, ★검출 실패를 「없음」으로 단정하는 설계는 문헌 기준으로도 위험합니다.
★판정은 ★**엔진이 규칙으로** 합니다(고정 원칙 5) — LLM 은 해석 문장에만 관여합니다. ★★**임계는
숫자가 하나도 정해져 있지 않습니다** — 제이의 유형 라벨이 온 뒤 그것을 맞추도록 정하고, ★**정한
뒤에는 고치지 않습니다**(고치려면 ADR). 「결과를 보고 임계를 무르는 것」이 2026-05 의 실패 형태입니다.
★평가는 단순해집니다 — **축별 분류 정확도 · ★혼동 행렬 · ★UNCERTAIN 비율(양방향 감시) · 유형별 샘플 수**.
★**clDice·Dice 는 폐기가 아니라 역할이 바뀝니다** — 합격 판정의 주지표에서 ★**U-Net 자체의 건강 검진**
으로. 구현과 합성 검증 8종은 그대로 유효하고, 「전부 선」에 clDice 1.000 이 나오는 병리도 그대로이므로
★**3중 조건은 유지**합니다. ★★**제이의 라벨 부담이 5~5.5시간 → 약 1.5시간으로 줄어듭니다.** 다만
★**전량이 아니라 10장은 픽셀 라벨을 유지**해야 합니다 — 임계를 정하려면 「정답 선이 어디인가」가
필요하기 때문입니다. ★그리고 제이 본인의 `confidence` 열을 두어 ★**`low` 인 것은 임계 보정에서
제외**합니다 — 흔들리는 정답으로 임계를 맞추면 안 됩니다. ⟹ 다음은 ★**P-27 라벨규칙 v2**이고,
★**제이가 라벨을 시작하기 전에 나와야 합니다.**

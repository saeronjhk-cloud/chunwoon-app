# 0. ★★★진단 — 제이 가설의 정정

**제이 가설**: 「손금에 대한 **학습이 되어 있지 않기** 때문에 실패했다」
**실측 판정**: ★**절반만 맞다.**

| 사실 | 증거 |
|---|---|
| 손금은 **실패가 아니라 정직성 원칙으로 제거**됐다 | 노션 `[2026-05-15]` v3.22.0 · 1,640줄 순삭제 · 「진짜가 아니면 삭제하는 게 나을 것 같아」 |
| ★**손금선 U-Net 을 학습까지 해뒀다** | `palm-api/unet_model.py` = "U-Net with **Context Fusion Module** for **Palm Line Segmentation**" · `checkpoint_aug_epoch70.pth` (55MB · epoch 70 · augmentation) |
| ★★**그 모델이 배포에 안 들어갔다** | `requirements.txt` 에 **`torch` 없음** · `palm_detector.py` 에 torch import **0건** · 체크포인트 참조 **0건** |
| 실제로는 경량 **Caffe ENet**(1.5MB)을 썼다 | `cv2.dnn.readNetFromCaffe(palm.prototxt, palm.caffemodel)` |
| 실패하면 **선을 지어냈다** | `_fallback_line()` — 손목·엄지·검지 랜드마크의 **거리 비율**로 생명선 좌표 생성. **입력 이미지의 주름과 무관** |

⟹ **「의사난수 40%」의 실체 = 학습 부족이 아니라 「학습한 것을 안 쓰고 폴백으로 때움」.**

### ★그래서 이번엔 다르다 — 이미 있는 자산
```
✅ U-Net + Context Fusion 아키텍처        ✅ epoch70 학습 체크포인트 (품질 미검증)
✅ FastAPI + Dockerfile (Cloud Run)       ✅ MediaPipe 손 검출 + palm region 추출
❌ 선 분류 로직 (_classify_lines)  ★자산 아님·부채   ✅ 제이 Colab 학습 경험 (YOLOv8)
✅ 관상이 이미 증명한 「측정은 진짜 · 해석은 면책」 패턴
```

### ★★그리고 결정적 통찰 하나
손바닥 주요 주름은 **해부학적으로 실재하는 구조물**입니다(태생기 형성 · 유전 관여).
⟹ **검출은 과학적으로 성립합니다.** 비과학인 것은 **해석**입니다.
⟹ 관상과 **같은 논리**가 손금에도 적용 가능해집니다 — 2026-05 판단을 뒤집을 **유일한 축**입니다.
★단 이 전제는 자문 Q1 로 **외부 검증 중**입니다.

|---|---|---|---|

### ★0-3 이 이 계획의 병목입니다
제이가 하루 1~2시간 쓸 수 있는 3주 중 **1주를 여기에** 씁니다.

**촬영 규격 (제이용)**
```
· 손바닥이 화면을 채우게 · 손가락은 자연스럽게 편 상태
· 밝은 곳 · 그림자 최소 · 플래시 금지(주름이 날아감)
· 한 사람당 좌·우 각 2장 (조명·각도 다르게)
· ★다양성이 핵심: 피부색 · 나이 · 손 크기 · 실내/실외
· 목표 30~50장 (자문 D3 회신이 오면 조정)
```
★**개인정보**: 손바닥 사진은 생체정보입니다. 평가용 수집 시
 **⑴동의 받기 ⑵로컬에만 보관 ⑶학습 후 폐기** 를 지키십시오. 이건 §5에서 다시 다룹니다.

**라벨링**
- ★★**정정 (2026-08-23 · 라벨규칙 v1 §9-2)** — 아래 3줄은 **폐기**되었습니다:
  ~~도구: 브러시로 선 3개를 색 구분해 칠하기~~ → ★**labelme 중심선(linestrip) + 폭 3단계 태그**
  ~~한 장당 3~5분 → 40장 ≈ 2~3시간~~ → ★**장당 5~6.5분 · 40~50장 ≈ 총 5~5.5시간**
  ~~라벨 규칙 문서 미작성~~ → ★**작성 완료**: `천운_손금_라벨규칙_v1_2026-08-23.md`
- ★**브러시를 쓰면 안 되는 이유**: 사람·날짜마다 굵기가 달라 mIoU 가 흔들립니다.
  중심선 + 규칙 확장이 재현성이 높고, ★**clDice 가 중심선 기반 지표라 정합**합니다.
- ★★**진짜 병목은 라벨링이 아니라 20~25명 섭외·촬영**입니다(라벨규칙 §7-4).

# 3. ★★평가 지표 — 여기서 속으면 안 된다

**같은 계열 접근(U-Net + Context Fusion)이 `F1 99.42%` · `mIoU 0.584` 를 동시에 보고한 사례를
확인했습니다.** 두 숫자가 왜 이렇게 벌어지는가:

```
손금선은 이미지 면적의 1~2%
⟹ 전부 "배경"이라고 답해도 픽셀 정확도가 98~99%
⟹ F1 도 같은 이유로 부풀려진다
⟹ ★mIoU 0.584 가 실질이다
```

⟹ **합격 판정에 F1 을 단독으로 쓰지 않습니다.**

| 지표 | 왜 |
|---|---|
| **mIoU** | 배경 편향을 덜 받는다 |
| ★**clDice** | 중심선 기반 · **연결성(위상) 보존**을 잰다. 손금선은 **끊기면 의미가 달라진다** (Shit et al., CVPR 2021) |
| 선별 검출률 | 3개 선을 **각각** 찾았는가 (전체 마스크가 아니라) |

★**합격 임계값은 아직 없습니다.** 자문 D3-3 으로 묻고 있고, 회신이 오면 확정합니다.
 ★임계값 없이 「좋아 보인다」로 넘어가면 **2026-05 와 같은 실패**입니다.

# 4. ★일정 — 3주 기준

```
1주차   Phase 0     라벨 규칙 문서 → 사진 수집 → 라벨링 → 평가 하네스
2주차   Phase 1/1.5 판정 → (필요시) 재학습
3주차   Phase 2     서버 연결 · ONNX 검토 · 판독 불가 경로
────────────────────────────────────────────────────
복귀 후  Phase 3/4   앱 통합 · 게이트 · 결제 연동
```

★**3주 안에 출시까지는 무리**입니다. 목표를 **「검출이 진짜인지 숫자로 판정하고, 진짜면 서버까지 연결」** 로 잡았습니다.
★앱 통합(Phase 3)은 결제·약관·게이트가 얽혀 있어 **복귀 후 본체 작업과 함께** 하는 것이 안전합니다.
★자문 반증④ 로 「3주는 무리인가」를 직접 묻고 있습니다.
